# サイト更新履歴の更新

更新履歴の元データは`src/content/changelog.yaml`だけにある。ページ上部の表示はここから作るので、書き換えるのはこのファイルだけでよい。

## 1. 載せる変更を集める

最後に載せた日付より後のコミットを、日本時間の日付ごとに見る。

```bash
TZ=Asia/Tokyo git log --no-merges --date=format-local:%Y/%m/%d --pretty='%ad %s' --since='<最後に載せた日付の翌日>'
```

ユーザーから載せる内容を直接言われたときは、それを優先する。

## 2. 載せるかどうかを決める

お客さんから見て分かる変化だけを載せる。迷ったら「お客さんに伝える意味があるか」で決める。

| 載せる | 載せない |
|---|---|
| ページや機能の追加・廃止(「かんたん注文フォームを追加」「特定商取引法に基づく表記を追加」) | 色・余白・文字サイズなどのデザインの調整 |
| メニュー・価格・送料・支払い方法の変更(「メニューと価格を更新」) | 文言の細かい言い回しの修正 |
| 写真の追加・入れ替え(「写真を追加」) | リファクタ・テスト・CI・依存パッケージの更新(`refactor:` `test:` `ci:` `chore(deps):` `fix(deps):`) |
| 注文・問い合わせの方法の変更(「LINE公式アカウントでのご注文に対応」) | 表示崩れなどの小さな不具合の修正 |
| 店舗情報・営業案内の変更 | SEO用のファイル(sitemap・JSON-LDなど)だけの変更 |

## 3. `src/content/changelog.yaml`に書く

- 1日を1項目にまとめる。新しい日付を一番上に足す。同じ日付がすでにあれば、その`items`に足す。
- 日付は`yyyy/MM/dd`(日本時間)。
- 1行は「〇〇を追加」「〇〇を更新」「〇〇に対応」「〇〇を掲載」のような、体言+動詞の短い形にする。句点は付けない。
- 1日に似た変更が並ぶときは1行にまとめる(写真を3枚足しても「写真を追加」1行)。
- 過去の行は、誤りでない限り書き換えない。

```yaml
- date: 2026/11/03
  items:
    - 写真を追加
    - 新しい豆をメニューに追加
```

## 4. 確かめる

```bash
npm test
npm run build
```

`src/content/changelog.test.ts`が、日付の形式(実在する日付か・未来でないか)、新しい順に並んでいるか、同じ日付が重複していないかを確かめる。

ページの内容が変わるので、`seo-files` skillの手順で`public/sitemap.xml`の`<lastmod>`を今日の日付にする。

## 5. 報告する

足した日付と行を一覧で示す。載せなかったコミットのうち、載せるか迷ったものがあれば一言添える。
