# メニュー・価格の更新

メニューの元データは`src/content/menu.ts`の`MENU`だけにある。サイトのメニュー表示、注文フォームの商品・価格、SEO用の価格帯はすべてここから作るので、書き換えるのはこのファイルだけでよい。

## 1. 元資料を読む

メニュー表の画像はReadで開き、全品目の品名・補足(産地や農園)・100g/200gの価格・カテゴリを書き出す。画像の誤字はサイト側で直し(例: `SINGRE`をシングルに)、直した箇所をユーザーへの報告に含める。

単位がほかと違う品目(例: パナマの20g/100g)は画像のとおりに転記し、報告で確認を求める。画像に載っていない既存の品目は勝手に消さず、ユーザーに確認する。

画像にLINEなどのQRコードがあれば、OpenCVの`wechat_qrcode_WeChatQRCode`でURLを読める。通常の`QRCodeDetector`は、中央にロゴがあるQRコードを読めない。

## 2. `src/content/menu.ts`を書き換える

| 定数・項目 | 内容 |
|---|---|
| `MENU_START_DATE` | 改定日。`"2026年10月1日"`の形式。注文文にも入る |
| カテゴリの`kind` | 豆は`"bean"`、ドリップバッグは`"drip"`。送料の数え方(1袋=1、1セット=0.5)が変わる |
| カテゴリの`sizes` | `["100g", "200g"]`のようなサイズの並び |
| カテゴリの`limited` | `true`にすると、枠とLIMITEDラベルと「なくなり次第終了」が付く |
| 品目の`name`・`sub` | 品名と補足(産地や農園)。補足がなければ`""` |
| 品目の`prices` | `sizes`と同じ順の価格(数値)。時価は`null` |
| 品目の`sizes` | カテゴリと違うサイズのときだけ書く(例: パナマの`["20g", "100g"]`) |
| 品目の`roasts` | 焙煎度を絞るときだけ書く(例: `["浅煎り"]`で「浅煎りのみ」と表示) |

サイズの見出し、「豆・粉　／　浅煎り…」の注記、品目の補足行に出るサイズや「浅煎りのみ」は、どれもこのデータから自動で作る。補足の文字列にサイズを書き足さない。

カテゴリの番号(01〜04)は配列の順番から付く。注文フォームの商品IDは「カテゴリ名/品名/補足」なので、同じカテゴリに同じ品名を並べるときは補足を変える。品名や補足を変えると、お客さんの端末に保存されたカート内のその品目は読み込み時に捨てられる。

送料(`SHIPPING_YEN`)は`src/order/pricing.ts`に、LINEのアカウントIDと支払い方法(`PAYMENTS`)は`src/content/shop.ts`にある。

## 3. SEO用の値

`index.html`の説明文の最安値とJSON-LDの`priceRange`は、ビルド時に`MENU`から自動で入る(`index.html`には`__PRICE_MIN__`・`__PRICE_RANGE__`の目印だけがある)。手で直すのは、支払い方法が変わったときのJSON-LDの`paymentAccepted`だけ。`src/content/shop.ts`の`PAYMENTS`と同じ並びで、`, `区切りにする。

そのあと`public/sitemap.xml`の`<lastmod>`を今日の日付にする。手順は`seo-files` skillに従う。

## 4. 確かめる

```bash
npm test                                          # 送料・合計・注文文の計算
npm run build
grep -o '¥450 / ¥850' dist/index.html | head -1   # 新しい価格がHTMLに出ているか
grep -o '"priceRange": "[^"]*"' dist/index.html   # 価格帯が新しい最安値〜最高値になっているか
```

ビルドの最後にプリレンダーが実行され、`dist/index.html`にメニューが書き出される。新しい品名と価格がgrepで見つかれば反映できている。

見た目は`npm run dev`を実行し、http://localhost:3000 の`#menu`で確かめる。スマホ幅(390px)で品名や価格が折り返していないかも見る。
